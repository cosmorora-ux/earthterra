# 전투 관리 프로그램 (웹 멀티플레이어)

여러 명이 동시에 접속해 진행하는 PvP/점령전/레이드 전투 관리 시스템입니다.
원래는 운영진 1인용 Tkinter 데스크톱 계산기(`gui.py`)였다가, Flask + Socket.IO 기반의
**방(room) 단위 웹 서버**로 확장되었습니다. 운영진(GM)이 서버를 띄우면, 참가자들은
공유 링크로 접속해 각자 자기 캐릭터를 조작하고 실시간으로 같은 화면을 봅니다.

## 실행 방법

```bash
.venv\Scripts\python.exe webapp.py
```

기본적으로 `http://127.0.0.1:5000` 에서 실행됩니다. 방 목록 화면(`/`)에서 전투 유형을
고르고 방을 만들면 운영진 화면으로 이동하며, 그 화면에 참가자 공유 링크가 표시됩니다.
같은 네트워크 밖에서도 접속하게 하려면 Cloudflare Tunnel 등으로 이 포트를 외부에 노출하면 됩니다.

**개발 서버 특성 (중요)**: Flask 디버그 리로더가 켜져 있어서, `.py` 파일을 수정하면 서버가
자동 재시작되며 **메모리에만 있는 방(ROOMS) 상태가 전부 사라집니다** (진행 중이던 전투도
초기화됨). `.html` 템플릿 수정은 `TEMPLATES_AUTO_RELOAD`로 즉시 반영되고 재시작이 필요 없습니다.
캐릭터 데이터(`characters.json`)와 수식 설정(`formulas.json`, `formula_profiles.json`)은
파일로 저장되므로 서버 재시작과 무관하게 유지됩니다.

## 폴더 구조

```
battle_manager/
├── webapp.py              # Flask + Socket.IO 서버 (역할/권한, 방 이벤트, 전투 액션 라우팅)
├── rooms.py                # 방(RoomState) 상태 — 메모리 전용, 서버 재시작 시 소실
├── battle.py                # Battle/GameManager — 턴·라운드·되돌리기·전투 규칙 엔진
├── models.py                # Character, Skill(공격/방어/힐/이동 등) 클래스
├── config.py                # 전투 수식·상수 + 전투 유형별 override 로직
├── templates/
│   ├── index.html          # 방 만들기 화면 (전투 유형 선택)
│   ├── gm.html               # 운영진 화면
│   └── guest.html            # 참가자/관전자 화면
├── static/music/            # 업로드된 mp3 (배경음악)
├── characters.json          # 캐릭터 데이터베이스 (파일 저장)
├── formulas.json             # 전역(PVP) 전투 수식 override (파일 저장)
├── formula_profiles.json      # 점령전/레이드/매스레이드 전용 수식 override (파일 저장)
│
├── gui.py, database.py, main.py   # 예전 Tkinter 단일 사용자 버전 (레거시, 웹 서버와 무관)
```

## 전투 유형 4종

방을 만들 때 아래 중 하나를 고릅니다. 같은 `battle.py`/`models.py` 엔진을 공유하며,
유형별 차이는 `webapp.py`가 `Battle`/`Character`에 옵션을 얹어주는 방식으로 구현되어 있습니다
(엔진 자체는 전투 유형을 모릅니다).

- **PVP** — 러너 vs 러너 (3:3 기본). 양쪽 다 참가자가 조작.
- **점령전(siege)** — GM이 조작하는 "거점" vs 러너 5~6인.
  - 매 라운드 시작 시 GM이 🎲 전조 다이스(1~3)를 굴려 거점이 이번 라운드 몇 번 행동할지 미리 안내.
  - 거점은 공격 1회당 자동 방어 1회(1~30 굴림)가 붙고, 행동은 방어정산/공격/힐만 가능.
  - GM은 거점의 공격/방어 굴림을 러너에게 공개하기 전 운영진 로그에서만 미리보고, 마음에
    들면 공개(reveal), 마음에 안 들면 되돌리기(undo) 후 재굴림 가능.
- **레이드(raid)** — GM이 조작하는 보스 vs 러너 다인(10~30인).
- **매스 레이드(mass_raid)** — 레이드의 격자 이동 버전. 12×12 격자에 몹은 중앙, 러너는
  나머지 칸에 배치. 매 라운드 자기 행동 전에 먼저 이동을 선언할 수 있음(행동력 소모 없음).
  - 이동 가능 칸수 = `AGILITY_MOVE_BASE + 민첩 × AGILITY_MOVE_PER_POINT` (기본 1~6칸)
  - 이동 가능 모양은 사각형이 아니라 **십자(상하좌우로 이동범위만큼) + 본인 주변 8칸**
    (`config.is_within_move_shape`). 뷰어 지도에서 아군을 클릭하면 이동 전엔 이 범위가,
    이동 후엔 고정된 사거리(십자 3칸 + 주변 8칸)가 하이라이트되며, 하이라이트된 빈 칸을
    다시 클릭하면 그 칸으로 바로 이동합니다.

전투 유형별 다이스/스탯 수식은 따로 저장됩니다 (PVP는 전역 `formulas.json`, 나머지는
`formula_profiles.json`의 해당 프로필). 각 화면의 "⚙ 전투 수식 설정"에서 수정 가능합니다.

## 역할과 권한

- **운영진(gm) 링크**: 캐릭터 등록/팀 편성/전투 시작/수식 수정 등 방 설정 전체를 조작. 운영진
  로그(다이스 세부값)도 볼 수 있음.
- **참가자(guest) 링크 + 닉네임**: 입력한 닉네임이 현재 전투에 참여 중인 캐릭터 이름과
  일치하면 그 캐릭터만 조작 가능. 닉네임을 "GM"으로 입력하면 참가자 링크로도 전체 조작 가능
  (`webapp.py`의 `resolve_control`). 일치하는 캐릭터가 없으면 관전만 가능.
- 권한은 서버(webapp.py)가 소켓 이벤트마다 재검증하므로, 클라이언트 코드를 우회해도 뚫리지 않음.

## 핵심 설계 철학 (전투 수식)

- **정신** = 다이스 **최소치(안정성)** — 재굴림 기준치(정신 × 3) 이하가 나오면 한 번 다시 굴려
  더 높은 값을 채택.
- **이능** = 다이스 **최대치/면수(폭발력)**
- **공격/방어** = 각 행동의 **직업 특화 보조치** (기본 다이스에 스탯 × 배율만큼 더해짐)
- **민첩/행운** = **크리티컬** 확률·배율 담당 (행운=확률 주 요인, 민첩=배율 주 요인)
- 피해는 **지연 정산**됩니다: 아직 이번 라운드 행동하지 않은 대상을 공격하면 "보류" 상태가 되고,
  대상이 방어/회피/힐 등으로 대응한 뒤 한꺼번에 정산됩니다.
- 다운(빈사) 상태: 자기 턴이 아직 안 온 캐릭터가 HP 0이 되어도 즉시 죽지 않고, 자기 팀 전원이
  행동을 마쳐야 생사가 확정됩니다 (그 사이 힐로 살릴 수 있음).

수식 상수와 각 항목의 계산식 설명은 `config.py`에 전부 주석으로 정리되어 있습니다.

## 배경음악

방 하나당 하나의 음악(유튜브 링크 또는 업로드한 mp3)을 재생할 수 있고, 서버가 재생 시작
시각(`started_at`)을 기준으로 모든 접속자의 재생 위치를 동기화합니다. 유튜브는 임베드 제한/
자동재생 정책에 따라 완전히 신뢰할 수는 없어서, "반드시 동시 재생"이 중요하면 mp3 업로드를
권장합니다 (네이티브 `<audio>`는 테스트에서 항상 안정적으로 동작).

## exe로 빌드하기 (레거시 Tkinter 버전만 해당)

```bash
pip install pyinstaller
pyinstaller --onefile --noconsole --name PvP전투관리 main.py
```

웹 서버(`webapp.py`)는 빌드 대상이 아니며, Python 환경에서 그대로 실행합니다.
